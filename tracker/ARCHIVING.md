# Архивирование задач

В Django-админке откройте **Tracker → Задачи**, отметьте одну или несколько задач
и выберите **«Архивировать выбранные задачи»**. Проверьте количество задач на
странице подтверждения. Для всего отфильтрованного списка используйте стандартную
ссылку Django «Выбрать все …», появляющуюся после выбора всей страницы.

Действия архивирования и восстановления доступны только активным Superuser.
Отдельные роли или разрешения не добавляются. По умолчанию список показывает
активные задачи; фильтр **«Архив»** переключает его на архивные или все задачи.
Для возврата выберите **«Восстановить выбранные задачи»** и подтвердите действие.

Архивные задачи и артефакты доступны Superuser в админке только для чтения.
Недельная история показывается в карточке архивной задачи. Чтобы изменить или
физически удалить архивную задачу, сначала восстановите её.

Архивирование сохраняет бизнес-статус, исполнителя, содержимое, идентификаторы,
связи и даты изменения задачи и связанных записей. Дата и автор архивирования
хранятся отдельно. При восстановлении эти два поля очищаются; события обеих
операций остаются в стандартном журнале Django-админки. Повторная операция
не изменяет уже достигнутое состояние. Пропущенные недели не создаются.

Пользовательские списки, поиск, сводки и Excel-выгрузки исключают архив.
Прямые ссылки и запросы изменения архивной задачи возвращают 404 для всех
пользовательских ролей, включая Superuser вне админки. После восстановления
применяются текущие правила доступа.

## Служебные команды и разработка

- `clear_tracker_data` удаляет только активные задачи и их связанные записи.
- `import_tasks --replace-existing` заменяет только активные задачи.
- `import_weekly_statuses --replace-existing` заменяет историю только активных
  задач. Номер архивной задачи без активного соответствия не принимается.
- Проверки ожидаемого количества в этих командах учитывают только активные данные.
- Импорт задач создаёт новые активные записи, даже если внешний номер совпадает
  с архивной задачей. Архивная запись не обновляется и не восстанавливается.
- `Task.objects` и обратные менеджеры задач возвращают только активные записи.
  `Task.all_objects` используется для явного доступа к архиву. Базовый менеджер
  остаётся нефильтрованным, чтобы связи и работа Django с ними сохранялись.
- Менеджеры артефактов и недельных статусов не фильтруют архив автоматически.
  В новых пользовательских запросах к ним, а также при SQL JOIN/агрегациях
  по задачам, необходимо явно применять `task__archived_at__isnull=True`.

Миграция добавляет поля архива; существующие задачи остаются активными.
Само применение миграции ничего не архивирует.
